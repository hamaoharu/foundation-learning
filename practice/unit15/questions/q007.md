# Unit 15 / Q007：最終統合問題—例外を呼び出し元へ伝える

## 問題

JSON文字列から有効なユーザー名を抽出し、成功・失敗をオブジェクトで返します。

処理を次の2ファイルへ分けてください。

```text
main.mjs → user-service.mjs
```

`user-service.mjs`で起きた例外はそこで握りつぶさず、`main.mjs`の`catch`まで伝播させます。

## `user-service.mjs`

`parseActiveUserNames(jsonText)`を名前付きexportしてください。

処理の順序：

1. `JSON.parse(jsonText)`でJSON文字列を解析する
2. 解析結果が配列でなければ、次の例外をthrowする

```js
throw new TypeError("users must be an array");
```

3. `active`が`true`のユーザーだけを`filter()`で抽出する
4. `map()`で各ユーザーの`name`を`trim()`し、名前の配列を返す

正常な例：

```js
parseActiveUserNames(`[
  { "name": "  Haru  ", "active": true },
  { "name": "Aki", "active": false },
  { "name": "  Sora", "active": true }
]`);
// ["Haru", "Sora"]
```

## `main.mjs`

`createUserResult(jsonText, logs)`を名前付きexportしてください。

- `try`の最初で`logs`へ`"start"`を追加する
- `parseActiveUserNames(jsonText)`を呼ぶ
- 成功時は次のオブジェクトをreturnする

```js
{
  ok: true,
  names: ["Haru", "Sora"],
}
```

- 失敗時は`catch`で次のオブジェクトをreturnする

```js
{
  ok: false,
  error: "SyntaxError: ...",
}
```

`error`の文字列は、`error.name`と`error.message`から作ってください。

- `finally`で必ず`logs`へ`"end"`を追加する

## 確認する3ケース

### 正常な配列JSON

```js
createUserResult('[{"name":" Haru ","active":true}]', logs);
// { ok: true, names: ["Haru"] }
// logs: ["start", "end"]
```

### 不正なJSON

```js
createUserResult("not json", logs);
// { ok: false, error: "SyntaxError: ..." }
// logs: ["start", "end"]
```

### 配列ではないJSON

```js
createUserResult('{"name":"Haru"}', logs);
// { ok: false, error: "TypeError: users must be an array" }
// logs: ["start", "end"]
```

## ルール

- `user-service.mjs`では`try/catch`を使わない
- `user-service.mjs`では`console.log()`を使わない
- `main.mjs`で`try/catch/finally`を使う
- `finally`からreturnしない
- 元データを変更しない
- 指定された依存方向を守る

node practice/unit15/answers/q007/main.mjs
