# Unit 5 / Q004 レビュー

## 修正後の確認

- 末尾の要素を`taken`へ保存：合格
- 末尾を除いた新しい配列：合格
- 空配列で`taken: null`：合格

- 元配列と`remaining`が別配列：合格

## 正しくできている点

- `slice()`で元配列とは別の配列を作っている
- `pop()`を元配列ではなくコピーへ使用している
- 新しいオブジェクトを返している
- 元配列を変更していない

## 必須の修正

### `pop()`の戻り値と変更後の配列を区別する

```js
const copied = ["A", "B", "C"];
const value = copied.pop();
```

この後は次の状態になる。

```js
value;  // "C"
copied; // ["A", "B"]
```

- `pop()`の戻り値が、取り出した要素`taken`
- `pop()`実行後のコピー配列が、残りの配列`remaining`

現在はこの2つが逆になっている。

### `slice(-2, -1)`は不要

`slice()`は配列を返すため、末尾の値そのものではなく配列になる。また、`slice(-2, -1)`は末尾ではなく末尾の1つ前を切り出す。

今回はコピー作成のための`slice()`と、末尾を取り出す`pop()`だけで実装できる。

### 空配列を`null`にする

空配列へ`pop()`すると`undefined`が返る。今回の仕様は`null`なので、コピーの`length`を確認してから`pop()`する。

## 実行結果

```text
["A", "B", "C"] → { taken: ["B"], remaining: "C" }
[42]              → { taken: [], remaining: 42 }
[]                → { taken: [], remaining: undefined }
```

## 次の完了条件

- `taken`が末尾の要素そのものになる
- `remaining`が末尾を除いた新しい配列になる
- 空配列では`{ taken: null, remaining: [] }`になる
- 元配列が変更されない

すべて達成した。
