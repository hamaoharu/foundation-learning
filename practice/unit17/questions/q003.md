# Unit 17 / Q003：rejected Promiseを`try/catch`で扱う

## 問題

次のコードを実行せずに読み、成功時と失敗時の流れを答えてください。

```js
function getUser(shouldSucceed) {
  if (!shouldSucceed) {
    return Promise.reject(new Error("user unavailable"));
  }

  return Promise.resolve({ name: "Haru" });
}

async function getMessage(shouldSucceed, logs) {
  try {
    const user = await getUser(shouldSucceed);
    logs.push("success");
    return `Hello, ${user.name}`;
  } catch (error) {
    logs.push(`error: ${error.message}`);
    return "Hello, guest";
  } finally {
    logs.push("end");
  }
}
```

## 問1

`getMessage(true, logs)`が返すものは、文字列そのものですか、Promiseですか。

## 問2

成功時、そのPromiseの最終的な成功値は何ですか。

## 問3

成功時の`logs`は最終的にどの配列になりますか。

## 問4

`getMessage(false, logs)`で`await getUser(false)`がrejectedになった後、同じ`try`内の`logs.push("success")`は実行されますか。理由も書いてください。

## 問5

失敗時、そのPromiseの最終的な成功値は何ですか。

## 問6

失敗時の`logs`は最終的にどの配列になりますか。

## 問7

失敗時でも、`getMessage()`が返すPromiseがrejectedではなくfulfilledになるのはなぜですか。
